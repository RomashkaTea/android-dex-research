# Android DEX 009 format notes

These notes describe the pre-release `dex\n009\0` format from Android build
`htc-29386.0.9.0.0`. The layout and opcode map were reconstructed from
`lib/libdvm.so` and validated against all 49 APK/JAR files in the build that
contain `classes.dex`.

All integers are little-endian. Offsets are absolute file offsets.

## Relationship to DEX 007 and DEX 012

DEX 009 is a transitional format:

- Its 92-byte header, class-ID table, 32-byte class definitions, and separate
  position/local debug tables match DEX 007.
- Its static-field lists have a four-byte alignment word after the count, as
  in DEX 012.
- Its method-list entries are 16 bytes and add a thrown-exceptions offset, as
  in DEX 012.
- Its normal opcode numbering matches DEX 007, while optimized
  `execute-inline` and `invoke-direct-empty` are newly present at `0xee` and
  `0xf0`.

## Header and identifier tables

```c
struct DexHeader009 {
    uint8_t  magic[8];           // "dex\n009\0"
    uint32_t checksum;           // Adler-32 of bytes [12, fileSize)
    uint8_t  signature[20];      // SHA-1 of bytes [32, fileSize)
    uint32_t fileSize;
    uint32_t headerSize;         // 92
    uint32_t linkSize, linkOff;
    uint32_t stringIdsSize, stringIdsOff;
    uint32_t stringObjectsSize;
    uint32_t classIdsSize, classIdsOff;
    uint32_t fieldIdsSize, fieldIdsOff;
    uint32_t methodIdsSize, methodIdsOff;
    uint32_t classDefsSize, classDefsOff;
};

struct DexStringId009 { uint32_t stringDataOff, utf16Length; };
struct DexClassId009  { uint32_t classNameIdx; };
struct DexFieldId009  { uint32_t classIdx, nameIdx, typeDescriptorIdx; };
struct DexMethodId009 { uint32_t classIdx, nameIdx, descriptorIdx; };

struct DexClassDef009 {
    uint32_t classIdx;
    uint32_t accessFlags;
    uint32_t superclassIdx;      // zero means no superclass
    uint32_t interfacesOff;
    uint32_t staticFieldsOff;
    uint32_t instanceFieldsOff;
    uint32_t directMethodsOff;
    uint32_t virtualMethodsOff;
};
```

Class-ID strings are bare binary names such as `java/lang/Object`; field types
and method descriptors use descriptor syntax. String data is NUL-terminated
modified UTF-8, with its UTF-16 length stored in the string-ID record.

## Variable tables

```c
struct DexClassList009 {
    uint32_t size;
    uint32_t classIdx[size];
};

struct DexInstanceFieldList009 {
    uint32_t size;
    struct { uint32_t fieldIdx, accessFlags; } entries[size];
};

struct DexStaticFieldList009 {
    uint32_t size;
    uint32_t padding;
    struct {
        uint32_t fieldIdx, accessFlags;
        uint64_t constantValue;
    } entries[size];
};

struct DexMethodList009 {
    uint32_t size;
    struct {
        uint32_t methodIdx;
        uint32_t accessFlags;
        uint32_t thrownExceptionsOff;
        uint32_t codeOff;
    } entries[size];
};
```

`thrownExceptionsOff` points to a `DexClassList009`.

## Code and debug information

```c
struct DexCode009 {
    uint16_t registersSize, insSize, outsSize, padding;
    uint32_t sourceFileIdx;
    uint32_t insnsOff;
    uint32_t exceptionsOff;
    uint32_t positionsOff;
    uint32_t localsOff;
};

struct DexPositionList009 {
    uint32_t size;
    struct { uint32_t address; uint16_t line; } entries[size];
};

struct DexLocalList009 {
    uint32_t size;
    struct {
        uint32_t startAddress, endAddress;
        uint32_t nameIdx, descriptorIdx, registerNumber;
    } entries[size];
};
```

Instruction lists and 16-byte exception records retain the early fixed-width
encoding. Exception, branch, position, and local addresses use 16-bit code
units.

## Opcode map

IDA's `dvmInterpretStd` dispatch table establishes this physical map:

- `0x00` through `0x2c` retain their logical meanings.
- Physical `0x2d` through `0x71` map to logical `0x2e` through `0x72`.
- Physical `0x72` through `0x76` are the five range invokes, logically
  `0x74` through `0x78`.
- `0x77` through `0x7a` are unused.
- `0x7b` through `0xe2` retain their logical meanings.
- `0xe3` through `0xed` are unused.
- `0xee` is `execute-inline`; `0xef` is unused.
- `0xf0` is `invoke-direct-empty`; `0xf1` is unused.
- `0xf2` through `0xfb` are quick field and invoke opcodes.
- `0xfc` through `0xff` are unused.

Packed and sparse switch payloads use `0x0100` and `0x0200` signatures with
signed 16-bit targets relative to the switch instruction.

## Using the tool

```sh
python3 tools/dex009.py -H app/Calculator.apk
python3 tools/dex009.py -d --class-filter 'Calculator;' app/Calculator.apk
python3 tools/dex009.py --smali-out out/smali app/Calculator.apk
python3 tools/smali009.py out/smali -o out/classes.dex
python3 tools/dex009.py --validate --json javalib/core.jar
python3 -m unittest tools/test_dex009.py
DEX009_CORPUS=/path/to/dex009 python3 -m unittest tools/test_dex009.py
```

The parser accepts raw DEX files and APK/JAR containers. Validation walks all
identifier, class, field, method, thrown-exception, code, catch, position,
local, instruction, branch, and switch structures and reports file-integrity
status.

Smali export includes class metadata, initial field values, thrown-exception
annotations, catches, branches, and switch payloads. Calculator's exported
Smali round-trips through `smali009.py` with identical class, method,
code-item, instruction, payload, and branch counts.

## Smali-to-DEX 009 assembly

`tools/smali009.py` emits native DEX 009 files. It builds the 92-byte header,
bare-name class IDs, padded static-field lists, 16-byte method records with
declared thrown-exception offsets, separate 28-byte code/debug records, early
switch payloads, and DEX 009 physical opcodes—including `execute-inline` and
`invoke-direct-empty`. The completed file is signed, checksummed, reparsed,
and validated before it is written.

```sh
python3 tools/dex009.py app/Calculator.apk --smali-out out/smali
python3 tools/smali009.py out/smali -o out/classes.dex
python3 tools/dex009.py out/classes.dex --validate
```

Existing outputs are protected unless `--force` is passed. `--no-validate`
supports malformed-file research. The 2,259-class DEX 009 `core.jar` has also
been exported and reassembled successfully, including 3,289 method
thrown-exception lists. Special constants are deliberately expanded to
ordinary Smali constants, so their wider encodings can introduce harmless
alignment `nop` instructions around switch payloads.
